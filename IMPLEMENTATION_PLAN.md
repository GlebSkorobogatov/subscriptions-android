# IMPLEMENTATION_PLAN — редизайн 2.1, малые задачи

16.11.2026. Цель — личная версия, без планов выпуска в магазинах. H — отдельная отложенная возможность. Не создавать проект с нуля. ID R0–R8 и I-01–04 являются целевым порядком. Никакой автоматической разработки после размещения документов.

## 1. Базовая точка и работа

База: актуальный HEAD `main` чистого снимка проекта с принятой документацией R0. Проверять SHA перед задачей, согласовать отдельную ветку. Не менять main кодовыми задачами, не объединять PR и не создавать ветки без согласия. Сохранять лицензии и schema snapshots. Старые проверки не являются приёмкой этого снимка.

## 2. Последовательность

Каждая строка — ограниченный этап; при необходимости разделить на ещё меньшие PR по указанным границам. После каждой задачи остановиться, отчёт владельцу, не переходить автоматически. Для промежуточного удаления зависимостей использовать компилируемые шаги; не оставлять видимые заглушки. Не смешивать рефакторинг и визуальную переработку без необходимости.

Тесты старых отменённых функций не являются новой регрессией; календарные/системные тесты сохранить и адаптировать. Временно несовместимую старую схему не открывать разрушительно. Не изменять данные пользователя для тестов.

## 3. Контроль объёма и качества

Готовность этапа: scope соблюдён, diff обозрим, применимые тесты реально пройдены, известные блокеры обозначены. Если GitHub Actions лимит исчерпан, выполнять разрешённые локальные команды на Windows/Android Studio, не запускать многократные одинаковые CI, не считать отсутствие CI PASS. Прежний облачный/локальный тестовый результат не переносится на новый SHA. Проверки на физическом Android-устройстве обязательны до PERSONAL-READY. Не запускать на платных ресурсах без согласования расходов. Не обновлять зависимости или CI ради редизайна без обоснования.

Команды в [AGENTS](AGENTS.md); отчёт: SHA/branch, изменение, PRD/T IDs, команды и результаты, окружение, блокеры, ручные шаги, следующий маленький этап. Если обнаружена новая продуктовая неоднозначность, не расширять scope, согласовать. До H — без заглушек, риск локальной потери принят явно.
