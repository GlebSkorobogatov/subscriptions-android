# ARCHITECTURE — редизайн 2.1

Дата 16.11.2026. Основание: [PRD](PRD.md), [решения №1–126](docs/redesign/DECISIONS.md). Это целевая архитектура, не описание уже реализованного состояния. Технические решения ниже конкретизируют требования, не расширяют продукт. Сохранить действующий проект, не переписывать его с нуля.

## 1. Базовое состояние и стек

База — чистый снимок существующего проекта с принятой документацией R0. Проверять актуальный HEAD перед задачей и получать разрешение на новую ветку. Предыдущие результаты CI не являются проверкой этого снимка.

Один модуль :app, Kotlin/Compose/Material3, MVVM/UDF, Navigation Compose, Room/KSP, DataStore, WorkManager, coroutines/Flow, JUnit/AndroidX/Compose Test. Сохранить applicationId, Gradle Wrapper, Version Catalog, текущие совместимые зависимости. На базе: JDK21, JVM target17, Gradle8.13, AGP8.11.1, Kotlin2.2.21, Compose BOM2025.10.01, SDK36, min31; проверить фактические конфиги перед задачей, не обновлять ради редизайна. Конструкторная DI, без новой многомодульности.

```text
Compose UI → ViewModel (immutable UiState, intents)
                ↓
    domain: Calendar / Lifecycle / Statistics / ReminderRules
                ↓
     Repository → Room / DataStore / private assets
                ↓
     Reminder reconciliation → WorkManager → NotificationManager
```

Domain — чистые функции, date/time передаются параметрами. UI не обращается непосредственно к DAO/NotificationManager. Репозиторий — единственный путь записи. Согласованный snapshot для календаря/статистики, тяжёлые операции вне main; реактивные изменения по данным/сегодня/настройкам, не persist вычисленные результаты. UI использует устойчивые ID; состояние форм — SavedStateHandle/сохраняемые черновики, изображения — временная локальная копия при необходимости.

CurrencyCode: предпочтительно убрать из целевой модели или сохранить технически как фиксированный RUB без иных веток. Все записи/импорт проверяют RUB; не маркировать старую иностранную сумму рублями. Хранить копейки Long, валидировать положительное значение, использовать checked add/multiply. Для нормализации — BigDecimal с достаточной точностью или точные рациональные дроби; финальное округление HALF_UP до копеек, суммировать до округления. UI графика может использовать Double только для геометрии после получения денежных итогов. Не считать цену с Float/Double. Переполнение/ошибка вычисления — явная ошибка, не частичная сумма или ноль.

Удалить из runtime: `payments`, `refunds`, `reminder_overrides`, PaymentSource/Intent, repositories/DAOs/commands/routes/screens подтверждений/истории/возвратов, RenewalMode, PAYMENT_ISSUE, AWAITING_RENEWAL, oneOffDueDate/overrideCycleIndex, cancellationLeadDays, cancellation event type, валютный выбор, настройки горизонта и фактических периодов, autoArchiveExpired и вызовы. Удалить старые ветки логики и неприменимые тесты с явным объяснением, сохранить регрессии дат, уведомлений, ассетов, безопасности. Исторические Room schema snapshots не переписывать задним числом.

### Переход схемы

№114 разрешает только ручной сброс тестовой базы перед приёмкой, не автоматическое стирание. Для этой тестовой ветки новая схема/версия Room, fresh install работает; старая неподдерживаемая схема вызывает понятное блокирующее состояние до ручной очистки владельцем. Не использовать `fallbackToDestructiveMigration` и catch→delete DB. Не подменять хранилище тихо новым именем. Если нужно, обнаружить старую схему до открытия или обработать исключение несовместимости; не запускать фоновые мутации до успешной инициализации. Сохранить исторические schema exports; задокументировать разрыв поддерживаемых версий. Очистка через настройки Android или явное ручное удаление тестовой установки владельцем; это удалит данные/настройки/изображения, заново выдать разрешение при необходимости. Без отдельной команды не очищать данные даже в тестовом окружении пользователя. После принятой новой базы все дальнейшие обновления с данными требуют безопасной миграции/тестов. Сохранить ActiveDataset, generation checks/gate и инфраструктуру изоляции H, не объявлять H готовым.

## 3. Календарный движок (R-CAL-01…03, R-SUB-04/07)

Единственная реализация для списка, деталей, статистики и напоминаний. Использовать существующий `DefaultRenewalCalendar` ([исходник](app/src/main/java/com/glebskorobogatov/subscriptiontracker/domain/calendar/RenewalCalendar.kt)), убрать разовые исключения и зависимость от подтверждения циклов, но не ломать bounded lookup и проверки диапазонов. Не требуется записывать индекс при ежедневном продлении; ближайший индекс вычисляется по опоре. Если текущий формат индекса полезен для нижней границы, оставить как внутреннюю метаинформацию серии, не как признак оплаты.

- Для DAY/WEEK: дата опоры плюс k*N (или 7*k*N) дней. MONTH: YearMonth опоры + k*N месяцев, день min(опорный, длина месяца). YEAR: год опоры + k*N, исходный месяц и день с тем же min. Не применять plusMonths цепочкой от уже усечённой даты.
- Серия стартует с указанной даты первого ожидаемого события; не прогнозировать даты до неё. Для нового/изменённого расписания первый ожидаемый платёж не раньше выбранной даты. В редакторе по умолчанию текущая ближайшая дата; если дата не была изменена, сохранить исходную опору, даже если отображаемая дата усечена. При явной смене даты/периода создать новую серию; если пользователю нужен 31 при вводе 28 февраля, сохранить существующее дополнительное уточнение опорного дня с проверкой согласованности первого события. Не превращать 28 в 31 автоматически.
- `nextDue(today)` = первая дата серии ≥today. Дни остатка = DAYS.between(today,due). Сегодня 0; завтра ближайшая дата автоматически меняется без записи. После долгого отсутствия — bounded direct lookup, не цикл по всем пропущенным годам. Явные ограничения на размер/представимость входных данных, без молчаливого усечения результата.
- Начало текущего периода: непосредственно предшествующая календарная граница (для первой будущей даты допустимо вычислить предшествующую регулярную границу как расчётное начало, не прошлый платёж). При явном уточнении использовать его только для указанного текущего периода; хранить связь с конечной границей, перестать применять после перехода/изменения графика. Если нет корректного начала, скрыть долю, не выдумывать факт доступа. Доля `clamp(days(today,end)/days(start,end),0,1)`, при start>=end скрыть. Остаток дней показывать независимо от возможности вычислить долю.
- Отмена фиксирует начало текущего периода на момент отмены и выбранный конец (exclusive); изменение конца не переносит исходное начало. Если конец <= today, индикатор скрыт; допустим прошлый конец при отметке уже произошедшей отмены. При unknown legacy end индикатор отсутствует; не создавать ложную дату. При возвращении в ACTIVE сбрасывать frozen end/start. Дата отмены по умолчанию nextDue, в день продления означает доступ уже закончился — пользователь может исправить.
- LocalDate/LocalTime/ZoneId. Date source единый, наблюдение при resume, local midnight, time/zone change. Не полагаться на перезапуск для обновления индикатора. Не переносить даты вслед за timezone, только определять сегодня и местное время отправки.

## 4. Жизненный цикл (R-LIFE-01…06)

| Команда | Предусловие | Эффект |
|---|---|---|
| Create | валидные поля | ACTIVE, ID, schedule |
| Edit | запись существует | изменить разрешённые параметры; state не меняется; price edit влияет на статистику; schedule edit reanchors |
| Cancel | ACTIVE | CANCELLED, frozen start/end, исключить расчёты/напоминания |
| EditEnd | CANCELLED | обновить end; state не меняется |
| Archive | ACTIVE/CANCELLED, явное подтверждение | ARCHIVED; исключить, сохранить параметры, archivedAt |
| Reactivate | CANCELLED/ARCHIVED, валидная форма проверки | ACTIVE, новая дата/период/цена, прежний ID, сброс данных отмены |
| Delete | запись существует, подтверждение | удаление, каскад ledger, отмена work/notifications, безопасная очистка assets |

Нет фоновых переходов состояния. Недопустимые команды отклоняются; изменение данных и сигнал reconciliation согласованы. Не считать отметку отмены отменой у провайдера. Обновления stats/read models не зависят от успешности уведомления. Сортировка активных по nextDue, отменённых по end null last, затем стабильный ID. Архив — дата архивирования по убыванию как технический порядок, затем ID; старые записи без даты не выдумывают дату. При архивации/удалении неактуальных деталей безопасный Back.

## 5. Статистика (R-STAT-01…06)

Использовать одну активную выборку и календарь, вычислять отдельно:

1. **30 дней**: half-open `[today, today.plusDays(31))`. Исправить существующий `plusDays(30)` в [ForecastEngine](app/src/main/java/com/glebskorobogatov/subscriptiontracker/domain/forecast/ForecastEngine.kt). Включать все повторения активных подписок, в том числе сегодня и today+30, не +31.
2. **12 корзин**: `[today, YearMonth.from(today).plusMonths(12).atDay(1))`, group by YearMonth, 12 месяцев включая пустые; текущий месяц только с сегодня. Детали — ровно события из соответствующей корзины, итог = сумма событий; sort date, ID. ExpectedCharge — вычисляемый DTO (subscriptionId, dueDate, amountMinor); без записи в БД.
3. **Нормализация**: year = price ×365/N (DAY), ×365/(7N) (WEEK), ×12/N (MONTH), /N (YEAR); month=year/12. Итог карточки и горизонтальный график используют общую реализацию. Округлять только отображение; дробные оценки не обязаны равняться сумме округлённых строк. Сортировать по точному значению, tie-break UUID. Одинаковые названия не объединять. Горизонтальный график не зависит от выбранного месяца. Пустой активный набор даёт нули; ошибка — error/retry.

Выбранный месяц в SavedStateHandle, при смене диапазона сохранять только если входит в 12 корзин, иначе текущий. Переключатель MONTH/YEAR хранится в DataStore. Суммы не хранятся как история; цена/удаление/отмена меняют оценки сразу. Никакой аналитики прошлых дат. Ограничить вычисления безопасным числом событий согласно календарю, не вводить незаметный лимит числа подписок. При слишком большом объёме/переполнении — явное сообщение, никаких частичных итогов.

## 6. Уведомления (R-NOT-01…04)

Адаптировать существующую инфраструктуру F-04, не заменять её упрощённой схемой без устойчивости. Из `ACTIVE` и общего набора offset вычислять due-offset по локальному календарю, момент отправки = localDate + время в текущем ZoneId (DST обработать стандартными java.time правилами). Учитывать короткие интервалы: напоминания разных циклов могут пересечься; дедуп по ID+due+offset+generation, не по имени. Планирование ближайших релевантных событий, ограниченный rolling horizon; не создавать задания на бесконечность. После изменения расписания/цены/глобального времени/offset/state пересогласовать устаревшие work и показанные уведомления; worker проверяет актуальную ревизию/поколение и соответствие события текущим данным непосредственно перед публикацией. Не использовать старую цену. Сохранить атомарный claim, lease recovery, retry, idempotent notification ID; ledger отмечает DELIVERED после подтверждения publisher, не обещать exactly-once при сбое между ОС и БД. Очищать устаревшие записи по безопасной ограниченной политике, не удаляя данные, нужные для дедуп.

После выключения устройства — одно наиболее актуальное ещё осмысленное напоминание на подписку среди пропущенных, не прошлый due. Запуск/resume/BOOT/time/timezone/settings changes запускают reconciliation. WorkManager best-effort, без exact alarm. Android 13+ POST_NOTIFICATIONS в контексте первого подходящего сохранения; deny/disabled не ломает данные. PendingIntent безопасный, открывает актуальные детали, при отсутствии ID — главный экран. Не запрашивать лишние разрешения. Отменённая/архивная запись не генерирует новые уведомления.

## 7. UI, хранение изображений, безопасность

Navigation Compose: Subscriptions, Statistics, Settings — корни; Archive, Details(id), Editor(id?), модальные селекторы. Восстановление идёт через редактор с явным режимом reactivation. Back stack сохраняет состояние вкладок, не открывает островок во вложенных экранах, безопасен при изменении данных/notification deep link. Состояние формы и выбранных параметров сохраняется при rotation/process recreation; не показывать успех до commit. Компоненты UI применяют №115–125 из дизайн-спецификации: компактный островок по центру, alpha фона 0,85; просторный список 54 dp; порядок графиков календарь → сравнение. Скролл панелей независим от горизонтального графика, учитывать insets/IME и accessibility. [UI_DESIGN_SPEC](UI_DESIGN_SPEC.md) — конкретные компоненты.

Сохранить G-02b: 12 офлайн-векторов Material Symbols и Apache 2.0 атрибуцию (исторический ADR-14 и license audit), системный Photo Picker, приватная копия и безопасная очистка общих assets. Не требовать доступ ко всей галерее; валидировать размер/формат/путь, не сохранять внешние URI как единственный источник. Не удалять используемый несколькими записями ассет. Не логировать приватные параметры, ключи и пути пользователя. Системный backup/D2D отключён. Отложенный H — [отложенный контракт](docs/redesign/DEFERRED_BACKUP.md).
