### Два подтверждённых отклонения и исправления

1. **Успех сохранения (UI_DESIGN_SPEC §4).** Капсула R3 существовала в галерее, а editor runtime только закрывал экран. Теперь существующий `EditorScreen.onSaved` запускает короткую капсулу «Изменения сохранены». Сигнал вызывается после `owner.perform` и подтверждённой фазы `done`. `TrackerRootChrome` размещает капсулу над измеренной областью островка либо над безопасной нижней границей вложенного экрана. Таймер интерфейса по умолчанию 2500 мс, учитывает рекомендованный accessibility timeout. Уведомления, навигационные решения и размеры панелей сохранены. Новый Android-тест держит запись перед commit, проверяет отсутствие капсулы и пустую таблицу, затем проверяет появление над островком после записи с ценой 12 345 копеек. **Компилируется, NOT RUN.**
2. **Восстановление после неопределённой записи периода (R6b).** Статистика блокировала переключатель и предлагала повтор сохранения. Если ответ потерян или запись постоянно отклоняется, со статистики нельзя было сверить результат с сохранёнными настройками. Появилось действие «Перечитать настройки». Оно вызывает существующий `SettingsViewModel.retryRead`, который отбрасывает ожидающий запрос после успешного чтения. Ошибка чтения сохраняет незавершённое состояние. Повтор записи по-прежнему задаёт исходное значение, а старое поколение защищено прежним контрактом. Соседние предпочтения и REG-02 механизм перечитывания DataStore сохранены. JVM-тест потерянного ответа, неуспешного и успешного перечитывания **PASS**. Обновлённый UI-тест доступности обеих кнопок **NOT RUN**.

Изолированный метод нужен при падении полного набора. Сначала сохранить исходный XML/логи тестового запуска, затем отдельно записать исход повтора. У метода `captureWhenSystemFontIsEnlarged` возможен ранний выход при штатном масштабе. Для соответствующей проверки требуются фактические 2.0 и кадры. Системные параметры менять только на тестовом устройстве и восстанавливать прежние значения.

ENV-01, Bash:

```bash
(
  set -e
  font=$(adb shell settings get system font_scale | tr -d '\r')
  motion=$(adb shell settings get global animator_duration_scale | tr -d '\r')
  restore() {
    if [ "$font" = null ]; then adb shell settings delete system font_scale; else adb shell settings put system font_scale "$font"; fi
    if [ "$motion" = null ]; then adb shell settings delete global animator_duration_scale; else adb shell settings put global animator_duration_scale "$motion"; fi
  }
  trap restore EXIT
  adb shell settings put system font_scale 2.0
  ./gradlew -Pf04DeviceTest=true :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.glebskorobogatov.subscriptiontracker.ui.R5bLifecycleUiTest#captureWhenSystemFontIsEnlarged' --no-daemon --max-workers=2 --console=plain
  adb shell settings put global animator_duration_scale 0
  ./gradlew -Pf04DeviceTest=true :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.glebskorobogatov.subscriptiontracker.ui.finance.LargeFontChartUiTest,com.glebskorobogatov.subscriptiontracker.ui.finance.FinanceNavigationTest' --no-daemon --max-workers=2 --console=plain
)
```

Windows, PowerShell:

```powershell
$font = (adb shell settings get system font_scale).Trim()
$motion = (adb shell settings get global animator_duration_scale).Trim()
try {
  adb shell settings put system font_scale 2.0
  .\gradlew.bat -Pf04DeviceTest=true :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.glebskorobogatov.subscriptiontracker.ui.R5bLifecycleUiTest#captureWhenSystemFontIsEnlarged' --no-daemon --max-workers=2 --console=plain
  if ($LASTEXITCODE -ne 0) { throw 'font-scale test failed' }
  adb shell settings put global animator_duration_scale 0
  .\gradlew.bat -Pf04DeviceTest=true :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.glebskorobogatov.subscriptiontracker.ui.finance.LargeFontChartUiTest,com.glebskorobogatov.subscriptiontracker.ui.finance.FinanceNavigationTest' --no-daemon --max-workers=2 --console=plain
  if ($LASTEXITCODE -ne 0) { throw 'reduced-motion test failed' }
} finally {
  if ($font -eq 'null') { adb shell settings delete system font_scale } else { adb shell settings put system font_scale $font }
  if ($motion -eq 'null') { adb shell settings delete global animator_duration_scale } else { adb shell settings put global animator_duration_scale $motion }
}
```

Для ручной проверки установить sandbox через `./gradlew -Pf04DeviceTest=true :app:installDebug` или `.\gradlew.bat -Pf04DeviceTest=true :app:installDebug`. Запустить `adb shell am start -n com.glebskorobogatov.subscriptiontracker.f04test/com.glebskorobogatov.subscriptiontracker.app.MainActivity`. На синтетических данных проверить офлайн в режиме полёта, смену темы, подписи TalkBack, доступность всех действий с IME, Photo Picker с локальным изображением и отказом. На API 33+ выполнить `NotificationPermissionUiTest` с тем же class-фильтром и вручную проверить отказ/разрешение и отсутствие запроса доступа ко всей галерее. Для process death свернуть приложение командой `adb shell input keyevent KEYCODE_HOME`, затем `adb shell am kill com.glebskorobogatov.subscriptiontracker.f04test`, открыть прежнюю задачу из Recents и сверить состояние. Для системного animator scale 0 дополнительно визуально проверить вертикальное движение панелей на длинном списке и горизонтальное движение графика до восстановления настройки.

Для реальных кадров открыть на sandbox карточку, прокрутить до календаря с выбранным месяцем, затем до рейтинга в обеих темах. Использовать `adb exec-out screencap -p > statistics-light-summary.png` в ENV-01 или `cmd /c "adb exec-out screencap -p > statistics-light-summary.png"` в Windows для сохранения бинарного вывода. Повторить с отдельными именами для месяца и рейтинга. Все кадры в этом отчёте **NOT RUN**. История R6-verify и ранее отложенные системные проверки сохраняются в [R6b](R6b.md), [R5b](R5b.md), [REG-01](REG-01.md) и [REG-02](REG-02.md).
