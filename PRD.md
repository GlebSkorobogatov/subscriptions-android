# PRD — «Подписки», редакция редизайна 2.1

Статус: целевая спецификация, решения владельца №1–126; реализация не начата в рамках этого комплекта. Дата: 16.11.2026. Прежние продуктовые требования заменяются настоящим документом. История решений: [DECISIONS](docs/redesign/DECISIONS.md). Все требования R-* обязательны для личной версии, кроме R-REL-03 (отдельная отложенная функция). Приложение предназначено для личного использования; выпуск в магазинах не планируется.

## 1. Цель и границы

- **R-BASE-01.** Локальный Android-менеджер регулярных платных подписок. Владелец вводит параметры один раз; приложение рассчитывает ближайшие даты, финансовую нагрузку и напоминает о продлении. Оно не списывает деньги, не проверяет оплату и не управляет аккаунтом поставщика.
- **R-BASE-02.** Kotlin, Jetpack Compose, Android 12+ (minSdk 31), русский интерфейс, смартфоны; приёмка на физическом Android-устройстве. Поддерживать портрет, landscape, системный масштаб текста, TalkBack. Без аккаунта, сети, рекламы, телеметрии и обязательных внешних служб.
- **R-BASE-03.** Только российские рубли. Суммы выражаются в рублях и копейках, не конвертируются. Не вводить другие валюты. Никаких внешних каталогов сервисов.
- **R-BASE-04.** Вне объёма: учёт реальных оплат и возвратов, подтверждения/неподтверждённые циклы, история цен, два режима продления, проблемные и просроченные состояния, разовые переносы, индивидуальные уведомления и напоминания об отмене, автоархив, поиск/категории/фильтры, ручная сортировка, бюджетные цели, банковская интеграция, сравнение плана с фактом. Нет отдельного trial, корзины и облачного аккаунта. Не добавлять заглушки для этих возможностей. Архив — не финансовая история.

## 2. Данные и редактор

| ID | Требование |
|---|---|
| R-SUB-01 | Уникальный стабильный ID каждой записи. Одинаковые названия разрешены; необязательная подпись аккаунта (например «Личный»). Название обязательно. |
| R-SUB-02 | Положительная цена в RUB, точность до копейки. Невалидный ввод блокирует сохранение с сообщением у поля. Никаких валютных селекторов. |
| R-SUB-03 | Периодичность: неделя, месяц, квартал (3 месяца), год; «Другая» — положительное целое N и единица день/неделя/месяц/год. 6 месяцев доступны через «Другая». |
| R-SUB-04 | Обязательная опорная дата ближайшего ожидаемого продления. Единое расписание; изменение даты/периодичности обновляет всю будущую серию, не один платёж. Неявное смещение опоры при чтении запрещено. |
| R-SUB-05 | Один из существующих 12 тематических офлайн-значков либо своё изображение из системного Photo Picker. Fallback «Другое». Выбор не меняет поля подписки. |
| R-SUB-06 | Создание и редактирование — отдельный полноэкранный редактор. Сохранение явное; исправления цены/даты/периода немедленно отражаются во всех расчётах после сохранения. Не терять черновик при повороте/пересоздании; Back с изменениями — подтверждение отказа. Значок по центру над полями (№123). |
| R-SUB-07 | Сохранять существующую возможность уточнить календарную опору (например 31 при ближайшей дате 28 февраля) и необязательное начало текущего периода для точности прогресса; держать их в компактном раскрываемом дополнительном разделе, не делать обязательными. При изменении расписания сбросить устаревшее уточнение, если оно не относится к новой серии. См. технические правила в ARCHITECTURE. |

## 3. Календарь, состояния и действия

| ID | Требование |
|---|---|
| R-CAL-01 | Активная подписка всегда имеет единое периодическое расписание. Ближайшая дата — первая дата серии, не раньше сегодняшней. В день события «Сегодня», переход на следующую дату на следующий календарный день. Приложение не создаёт записей о списаниях. |
| R-CAL-02 | Календарные месяцы/годы считаются от исходной опоры: если дня нет, использовать последний день месяца, в подходящем месяце восстановить исходный день. 31.01 → 28/29.02 → 31.03; 29.02.2028 → 28.02.2029 → 29.02.2032. Дни — точный интервал N календарных дней, недели — 7N; 31.01 + 30 дней в невисокосный год = 02.03. |
| R-CAL-03 | Даты — местные календарные даты, не UTC timestamps. При запуске, возврате в приложение, смене даты/часового пояса пересчитать актуальную дату/индикатор/статистику. После долгого отсутствия не генерировать историю. |
| R-LIFE-01 | Только ACTIVE (Активна), CANCELLED (Отменена), ARCHIVED (В архиве); названия хранения могут отличаться при однозначном отображении. Активные участвуют во всех расчётах и уведомлениях, остальные — нет. |
| R-LIFE-02 | Отмена: пользователь сообщает, что прекратил продление у поставщика. Подставить ближайшую дату продления как дату окончания доступа; дать изменить её. После сохранения исключить из статистики и уведомлений сразу. Дата окончания — первый день без доступа; при наступлении даты индикатор исчезает, плашка «Отменена» остаётся. Не отменять подписку у поставщика автоматически. |
| R-LIFE-03 | Архивирование только вручную. Отменённая подписка остаётся внизу списка сколько угодно. Из деталей доступно явное архивирование; также сохранить прежнее ручное действие архивирования активной записи с подтверждением исключения из расчётов. Архив хранит параметры и иконку, не отображается в списке активных/отменённых. |
| R-LIFE-04 | Возобновление отменённой и восстановление архивной подписки: проверить цену, периодичность, следующую дату; сохранить тот же ID и оформление; снова ACTIVE, сбросить данные об окончании доступа, пересчитать уведомления и статистику. Не создавать новую запись без команды добавления. |
| R-LIFE-05 | Окончательное удаление из деталей с явным предупреждением: запись исчезнет без восстановления; отменить уведомления, безопасно очистить только неиспользуемый ассет. Отказ не меняет данные. |
| R-LIFE-06 | Индикатор означает долю оставшегося расчётного периода, а не подтверждённый оплаченный доступ. Заполняется от 100% в начале до 0% в день продления. Отменённый индикатор использует зафиксированный конец доступа, не перескакивает на будущие даты; не показывать после конца или при неизвестной дате/некорректном начале. |

## 4. Экраны и пользовательские сценарии

| ID | Требование |
|---|---|
| R-UI-01 | Три корневых экрана: «Подписки», «Статистика», «Настройки». Компактный островок по центру, только на них; иконки без видимых подписей, с семантикой; мягкая капсула активной вкладки (№115–116). Настройки — корневая вкладка, архив внутри настроек. |
| R-UI-02 | «Подписки»: заголовок, плюс справа, плоский список без карточек/рамок/разделителей; никаких финансовых сводок на этом экране (№110). Активные по ближайшей дате, затем отменённые по дате окончания; неизвестная дата последней, при равенстве стабильный порядок по ID. Крупный заголовок в одной строке и круглый плюс. Просторные строки: значок 54×54 dp; название, подпись при наличии, дата и оставшееся время слева; цена и период справа; индикатор 4 dp под всей текстовой частью (№118–121), по R-LIFE-06. Отменённые приглушённые, но читаемые. |
| R-UI-03 | Пустой основной список: нейтральная контурная иллюстрация, краткое пояснение, «Добавить подписку». Нажатие строки открывает отдельные детали; редактор открывается из деталей. |
| R-UI-04 | Детали: выразительный значок, название, сумма, интервал, дата, срок/прогресс и состояние; основная информация выровнена влево (№124). Одно основное контекстное действие (активна — редактировать, отменена — возобновить, архив — восстановить); остальные допустимые действия в меню. Операции отмены/архива/удаления явные. |
| R-UI-05 | Архив — вложенный экран, читаемый приглушённый список без прогресса, с ценой и датой завершения/архива при наличии, открывает детали. Не создавать вымышленную дату. |
| R-UI-06 | Уже утверждённая дизайн-система ChatGPT-like; белый/графитовый фон, нейтральные компоненты, функциональные цвета, контурные иконки, мягкая геометрия. Подробности в UI_DESIGN_SPEC. Дизайн не переизобретать. |
| R-UI-07 | Верхняя панель и нижний островок на корневых экранах скрываются при содержательной вертикальной прокрутке вниз, возвращаются вверх; на коротких/пустых экранах и вверху видимы. Горизонтальный график не запускает скрытие. Анимации отключаются настройкой и системным reduce motion: скрытие/возврат мгновенные. |
| R-UI-08 | Темы светлая/тёмная/системная, настройка анимаций сразу после выбора темы. Настройки сгруппированы в мягко залитые карточки без рамок и разделителей (№125), общие напоминания, вход в архив. Состояние разрешения уведомлений, сведения о версии и локальном хранении; никаких заглушек H. |
| R-UI-09 | Полупрозрачные панели без blur; нижний островок с непрозрачностью фона 85%, иконки непрозрачные (№117); контраст и insets; при скролле контент может проходить позади, но последний элемент доступен полностью. Все действия ≥48 dp; доступность, IME, rotation, process recreation, Back и состояние вкладок проверяются. |
| R-UI-10 | Название приложения «Подписки»; утверждённый launcher-символ (№126): сплошной графитовый колокольчик, толстое незамкнутое кольцо с серым участком, белый фон. Сохранять форму, цвета и пропорции [утверждённого изображения](docs/redesign/assets/launcher-approved.png); убрать только внешнюю презентационную тень и адаптировать к маскам Android. |

## 5. Статистика (все показатели на одном экране)

| ID | Требование |
|---|---|
| R-STAT-01 | Только ACTIVE. Верхняя карточка: «Ближайшие 30 дней» (сегодня и следующие 30 дней включительно, 31 календарная дата), ниже «Расчётная стоимость за год». Средняя месячная сумма не дублируется в карточке. После карточки — календарный прогноз с детализацией месяца, затем горизонтальное сравнение (№122). |
| R-STAT-02 | Горизонтальный график сравнения стоимости подписок, переключатель «За месяц / За год». Нормализованные суммы по тарифам, не календарные списания; сортировка по убыванию стоимости, tie-break ID; разные записи одного сервиса отдельно. Сохранять выбор между запусками (адаптация №81). Не открывать историю при нажатии. |
| R-STAT-03 | Годовая нормализация: для N дней цена ×365/N, для N недель ×365/(7N), для N месяцев ×12/N, для N лет /N. Месячная нормализация = годовая /12. Это оценка стандартного 365-дневного года, не точный календарный итог. Точная арифметика до финального округления; не суммировать округлённые подписи. |
| R-STAT-04 | Вертикальный прокручиваемый график ожидаемых платежей за 12 календарных месяцев: от сегодня до первого дня месяца, следующего за 12-м отображаемым месяцем, исключительно. Текущий месяц неполный, прошлые даты не входят. Показать 12 корзин, включая нулевые; подписи месяца/года различимы. Никаких переключателей горизонта. |
| R-STAT-05 | Выбор столбца выделяет месяц; под графиком — сумма и перечень ожидаемых платежей выбранного месяца (название, подпись при наличии, дата, цена, все повторения). Сортировка по дате, при равенстве по ID. Горизонтальный график не зависит от выбора месяца. По умолчанию текущий месяц, восстановить допустимый выбор при пересоздании. |
| R-STAT-06 | Все показатели — расчёт/оценка, не фактические расходы. Цена/опора/состояние меняются — всё реактивно пересчитывается. Никакой исторической аналитики, хранения прогнозов как фактов или выбора прошедших периодов. При отсутствии активных записей — нулевые суммы и понятное пустое состояние; при ошибке не выдавать нулевую сумму за успешный расчёт. |

## 6. Уведомления

| ID | Требование |
|---|---|
| R-NOT-01 | Единые глобальные напоминания о ближайших продлениях активных подписок: набор {7,3,1,0} дней (можно несколько, пустой набор выключает). По умолчанию {3,1}; время 09:00 по текущему местному поясу. Индивидуальных правил и событий отмены нет. |
| R-NOT-02 | Работают без открытого UI через существующий механизм WorkManager, best effort, без exact alarm. Перепланирование при изменении подписки/общих настроек, запуске/перезагрузке, изменении времени/пояса, восстановлении данных. Сама дата подписки не смещается. |
| R-NOT-03 | Защита от дублей, устаревших workers и уведомлений отменённых/архивных/удалённых записей. После длительного отключения максимум одно актуальное сообщение на подписку за пропущенные напоминания, не отправлять истёкшие события. Нажатие открывает детали, если запись существует и доступна; иначе главный экран. |
| R-NOT-04 | Android 13+: контекстный POST_NOTIFICATIONS после первой подходящей сохранённой подписки; отказ не блокирует работу, не запрашивать назойливо. Состояние ОС показывается в настройках, можно открыть системные настройки. API31: учитывать отключение уведомлений. Не обещать точную минуту доставки. |

| ID | Требование |
|---|---|

При реализации обязательны H-01–H-05 и проверки безопасности/сбоев. Контракт [DEFERRED_BACKUP](docs/redesign/DEFERRED_BACKUP.md). |
